## 1. 研发目标

把**已验证可运行的高保真界面原型**（内置示例数据、交互全真）演进为**可交付成品**：
导入真实 DICOM → 一键 v3 自动分割 → 人工微调 → 实时面积 → 导出/工程 → 打包 exe，
满足需求说明书全部功能需求（FR-1 ~ FR-8）与验收标准（需求 §11）。

**起点**：原型（`_on_import`/`_on_auto` 目前弹提示，数据来自 `assets/sample.npz`）。
**终点**：`腹部CT体成分分析工具.exe`，非技术用户双击即用，全程离线。

---

## 2. 研发范围与原则

- **范围**（同需求 §1.3）：孤立单层轴位切片、只算面积、v3 阈值几何法、简体中文。
- **不在范围**（同需求 §1.4）：体积/多层、AI 模型、测量工具、矩形/椭圆/魔方/套索、肌间脂肪单列、PACS、3D。
- **核心原则**（承接设计 §1）：原型已把**数据模型 / 渲染 / 编辑 / 视图**打牢；
  后续各步以**新增文件 + 接线**为主，**不改动已验证的核心**，最大限度降低回归风险。

```
WP-1 抽算法 ─┬─► WP-3 一键分割 ─┬─► WP-4 批量 ─► WP-9 性能回归 ─┐
```

## 7. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| v3 抽取后与基线不一致 | 面积偏差 | WP-1 对拍脚本逐例逐像素比对，卡住回归 |
| 多厂商 DICOM 标签差异 | 读取失败/错值 | 收集各厂商样例，`dicom_io` 做字段兜底；缺 PixelSpacing 明确提示 |
| 批量分割冻结 UI | 体验差 | WP-4 强制 QThread，worker 不碰控件 |
| 脏器/肌肉 HU 重叠 | 自动结果需人工修 | 已在需求 §9 声明局限，界面保留微调闭环 + "已编辑"标记 |
| 中文导出乱码 | 数据不可用 | 强制 `utf-8-sig`（FR-6.4） |
| 打包后 Qt 插件缺失 | exe 无法启动 | WP-10 在干净机器验证；必要时 `--collect-all PySide6` |
| 未保存丢失编辑 | 数据损失 | WP-6 脏标记 + 关窗提示（FR-7.4） |
| 大例量内存占用 | 卡顿/崩溃 | 懒加载像素、`label` uint8、undo 快照上限 30 步 |

## 11. 性能回归记录（WP-9，2026-10-11）

本机：Windows 11 / RTX 3050 Laptop 4GB / WorkBuddy venv (Python 3.13)；数据：`ct/` 69 例真实切片。

| 指标 | 需求目标 | 实测 | 结论 |
|---|---|---|---|
| 批量导入（只读头） | ≤30s / 100 例 | 0.13s / 100 例（1.3 ms/例） | ✅ 远优 |
| 单例读取 + v3 分割 | ≤2s | 221 ms / 例 | ✅ |
| 编辑响应（paint_disk） | ≤200 ms | 0.65 ms / 次 | ✅ |
| 区域生长（grow_selection） | — | 0.7 ms / 次 | ✅ |
| 单例内存（hu+label+body） | — | 1.6 MB（peek） | ✅ 轻量 |

> 结论：懒加载 + `label` uint8 + undo 快照上限 30 步的设计有效，600+ 例规模无压力。

> 验证：`ct/` 导入 69 例、懒加载按选中例触发、真实数据区域生长与三图层互斥均通过；
